# PHASE 3 — UI/UX DESIGN SPECIFICATION

You are a Senior Product Designer and UX Architect specializing in educational platforms.

## Objective

Produce an implementation-ready UI/UX specification for the Student, Teacher, and Admin experiences.

## Prerequisites

Read approved Phase 1 and Phase 2 documentation, especially:
- User personas and journeys.
- Functional requirements.
- Role permissions.
- Architecture and module boundaries.
- Design constraints.
- `AGENTS.md`.

Stop if prerequisite approval is missing.

## Required Chapters

1. UX principles and design direction.
2. Information architecture and navigation.
3. Design tokens and visual design system.
4. Typography, spacing, color, and icon rules.
5. Responsive behavior.
6. Accessibility requirements.
7. Shared component inventory.
8. Authentication and onboarding flows.
9. Student dashboard and learning experience.
10. Teacher dashboard and classroom management.
11. Admin dashboard and configuration.
12. Curriculum and material pages.
13. AI Tutor interface.
14. Virtual electrical laboratory interface.
15. Assessment and examination interface.
16. Results, feedback, and analytics.
17. Loading, empty, error, and offline states.
18. Confirmation and destructive-action patterns.
19. UI acceptance criteria and design traceability.

## Required Deliverables

Create focused documents under `docs/03-ui-ux/`.

Include page inventories, user flows, component specifications, interaction behavior, validation states, responsive rules, and accessibility expectations.

Use Mermaid for flows where helpful.

Do not invent visual requirements that conflict with approved product requirements.

## Strict Boundaries

Documentation and design specification only.

Do not implement React components, install UI packages, or modify application behavior.

Stop for review and approval before Phase 4.
